## 1. 概述

### 1.1 问题 / 背景

`docs/v0.1.md` 已经定义了 v0.1 MVP 的目标目录结构（§3.3），但当前仓库骨架是早期 demo 留下的，与之有 4 处明显错位（详见上一版 spec 的差异表）：

- Electron 主进程在 `electron/main.js`（CommonJS 单文件、与 `frontend/` 平级），不是 `frontend/main/*.ts`
- 渲染层在 `frontend/src/`，未包到 `frontend/renderer/src/`
- backend 入口是 `cmd/main.go`，缺 `cmd/server/`、`internal/<domain>/`、`pkg/` 三层
- preload 是 `electron/preload.js`（TODO），不是 `frontend/preload/index.ts`

每加一个 v0.1 模块都要先解决"放哪儿"，会持续制造摩擦。

### 1.2 目标

把仓库骨架**严格**迁移到 `docs/v0.1.md` §3.3 的形态：

1. **目录结构**：`frontend/{main,preload,renderer}/` 三层归位；backend 三层（`cmd/server` + `internal` + `pkg`）就位；`resources/` 建立
2. **主进程 TS 化**：用 electron-vite 统一编译 main/preload/renderer，提供 HMR
3. **空骨架可运行**：迁移完 `npm run dev` 能起窗口、`npm run check` 全绿、hello 链路（点击 → `/api/hello`）正常
4. **质量门禁不退化**：oxlint / prettier / vitest / go test / commitlint / husky / i18n 双语 / shared 跨进程常量 / specs 框架全部保留
5. **AGENTS.md 同步更新**：根 + frontend + main + preload + renderer + backend 六份 AGENTS.md 与新结构对齐

### 1.3 非目标

- **不**实现 v0.1.md §2 的任何业务功能（聊天、OpenClaw、工具、四层记忆、审批）
- **不**碰 OpenClaw Gateway 对接（属于 v0.1 第 1-2 周业务 spec）
- **不**改 `shared/constants.ts` 内容、`specs/`、`.claude/`、`docs/`
- **不**改质量门禁的入口命令（`npm run check` 仍然全跑）
- **不**引入 electron-builder 打包（v0.1 第 4 周再上）
- **不**改 i18n 字典内容、`api/hello.ts` / `request.ts` / `services/i18n.ts` 等已有可工作代码

import { createWindow, getMainWindow } from './window';
import { registerIpc } from './ipc';
import { startGo, waitForGo, killGo } from './go';

function configureProxy(): void {
  const isDev = !app.isPackaged;
  session.defaultSession
    .setProxy({ mode: isDev ? 'direct' : 'system' })
    .then(() => console.log(`[main] proxy mode: ${isDev ? 'direct' : 'system'}`))
    .catch((err) => console.error('[main] setProxy failed:', err));
}

app.whenReady().then(async () => {
  configureProxy();
  startGo();

  try {
    await waitForGo();
  } catch (e) {
    console.error('[main]', (e as Error).message);
    killGo();
    app.quit();
    return;
  }

  registerIpc();
  createWindow();

  app.on('window-all-closed', () => {
    if (process.platform !== 'darwin') app.quit();
  });

  app.on('activate', () => {
    if (BrowserWindow.getAllWindows().length === 0) createWindow();
  });
});

app.on('before-quit', killGo);
app.on('will-quit', killGo);
process.on('exit', killGo);

#### 4.3.5 frontend/main/go.ts

```ts
import { spawn, type ChildProcess } from 'node:child_process';
import { join } from 'node:path';

let goProcess: ChildProcess | null = null;

export function startGo(): void {
  const backendDir = join(__dirname, '../../../backend');
  goProcess = spawn('go', ['run', './cmd/server'], {
    cwd: backendDir,
    stdio: ['ignore', 'pipe', 'pipe'],
  });

  goProcess.stdout?.on('data', (d) => console.log('[go]', d.toString().trim()));
  goProcess.stderr?.on('data', (d) => console.error('[go!]', d.toString().trim()));
  goProcess.on('exit', (code) => {
    console.log(`[go] exited with code ${code}`);
    goProcess = null;
  });
}

export async function waitForGo(retries = 100): Promise<void> {
  const url = 'http://127.0.0.1:8080/api/hello';
  for (let i = 0; i < retries; i++) {
    try {
      const r = await fetch(url);
      if (r.ok) {
        console.log('[main] Go backend ready');
        return;
      }
    } catch {}
    await new Promise((r) => setTimeout(r, 200));
  }
  throw new Error('Go backend failed to start in 20s');
}

export function killGo(): void {
  if (goProcess) {
    console.log('[main] killing Go process...');
    goProcess.kill();
    goProcess = null;
  }
}
```

#### 4.3.8 backend/cmd/server/main.go

```go
package main

import (
    "encoding/json"
    "log"
    "net/http"

    "darvin-cowork/internal/config"
)

func corsMiddleware(next http.HandlerFunc) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Access-Control-Allow-Origin", "*")
        w.Header().Set("Access-Control-Allow-Methods", "GET, POST, PUT, DELETE, OPTIONS")
        w.Header().Set("Access-Control-Allow-Headers", "Content-Type, Authorization")
        if r.Method == http.MethodOptions {
            w.WriteHeader(http.StatusNoContent)
            return
        }
        next(w, r)
    }
}

func main() {
    cfg := config.Default()
    http.HandleFunc(config.HttpBasePath+"/hello", corsMiddleware(func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "application/json")
        json.NewEncoder(w).Encode(map[string]string{"msg": "hello world"})
    }))

    log.Printf("[cowork] listening on %s", cfg.ListenAddr)
    if err := http.ListenAndServe(cfg.ListenAddr, nil); err != nil {
        log.Fatalf("[cowork] server error: %v", err)
    }
}
```

## 5. 边界情况

| 场景                                                                         | 处理方式                                                                                                         |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| electron-vite 与 Vite 8 兼容性                                               | 实施前先用 `npm view electron-vite versions` 确认最新版支持 Vite 8；如不支持，临时降到 Vite 7 并在 spec 备注     |
| `concurrently` / `wait-on` / `cross-env` 删除后，CI / 其他脚本有没有引用     | 用 grep 全仓搜 `concurrently` / `wait-on` / `cross-env`，只用在 npm scripts 里                                   |
| `package-lock.json` 锁了 `electron/main.js` 路径                             | 验证：lock 文件不含源码路径，删依赖后 `npm install` 自动重生成                                                   |
| `frontend/src/shared` symlink 移动时断裂                                     | §4.7 显式 rm + 重建                                                                                              |
| `backend/cmd/main.go` 与新 `cmd/server/main.go` 并存导致 `go run ./cmd` 歧义 | 实施顺序明确"先建新的 + 删旧的"，不并存                                                                          |
| `backend/cmd/main_test.go` 内容是否依赖 package path                         | 检查：`package main` 不变，import 路径如有 `darvin-cowork/cmd` 改成 `darvin-cowork/cmd/server`（实际看代码内容） |
| Windows 下 `electron-vite dev` 监听 5175 端口冲突                            | 文档化为已知行为；v0.1 第 1 周 spike 不在 Windows 测                                                             |
| `frontend/main/window.ts` 里 `__dirname` 在 ESM 下行为                       | electron-vite 编译为 CJS 输出，`__dirname` 可用；如不行用 `import.meta.url` + `fileURLToPath`                    |
| `preload` 类型导入（`import type { DarvinApi }`）跨 main/renderer 边界       | 用 `import type` 只走类型擦除，运行时不引入跨边界值导入                                                          |
| `oxlint` 对新 frontend/main TS 文件的规则                                    | 实施后跑 `npm run lint` 验证；按需调整 `.oxlintrc.json`（尽量不动）                                              |
| 删 `electron/AGENTS.md` 时历史引用                                           | grep `electron/AGENTS.md` 全仓，更新引用                                                                         |
| `docs/系统架构,md`（文件名带逗号）引用 electron 路径                         | 该文档为参考资料，spec 范围外，但实施时顺手 grep 看是否需要同步                                                  |

## 9. 风险

| 风险                                                                          | 概率 | 影响 | 应对                                                                                                                 |
| ----------------------------------------------------------------------------- | ---- | ---- | -------------------------------------------------------------------------------------------------------------------- |
| electron-vite 不兼容 Vite 8                                                   | 中   | 高   | 实施前先 `npm view electron-vite versions` + 看其 peerDeps；必要时降到 Vite 7（在 spec 备注）                        |
